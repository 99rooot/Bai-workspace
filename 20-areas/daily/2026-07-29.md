# 2026-07-29 작업 보고서

## 오늘의 목표

Mission 2의 결과물로 외부 API를 안전하게 연결하기 위한 `api-guide` 스킬을 만들고, 이 가이드를 실제 작업에 적용해 Google Calendar 일정을 기존 Slack 봇에서 확인할 수 있도록 확장하는 것이 목표였다.

최종적으로 확인하려는 사용 방식은 다음과 같다.

```text
Slack에서 봇에게 오늘·내일·이번 주·다음 주 일정을 물어본다.
→ Vercel에서 실행 중인 봇이 Google Calendar를 읽는다.
→ 요청한 기간의 일정을 Slack으로 답한다.
```

추가로 매일 밤 11시에 다음 날 일정을 자동으로 알려주는 기능도 준비했다. 다만 이 기능은 실제 예약 실행 시각이 되지 않아 아직 최종 동작을 확인하지 못했다.

## 오늘 한 것

### 1. Mission 2용 `api-guide` 스킬 제작

외부 API를 연결할 때마다 로그인, 권한, 비밀정보, 배포 방식을 처음부터 다시 판단하지 않도록 반복 가능한 가이드를 만들었다.

생성한 파일:

```text
.agents/skills/api-guide/SKILL.md
```

스킬 이름은 처음 계획했던 긴 이름 대신 기억하기 쉬운 `api-guide`로 정했다. 스킬에는 Mission 2에서 요구한 다음 구조를 포함했다.

- `Use when`: 어떤 요청에서 스킬을 사용할지
- `Input`: 연결 전에 확인할 정보
- `Judgment`: API 사용 여부와 최소 권한을 판단하는 기준
- `Steps`: 준비, 승인, 연결, 검증 순서
- `Output`: 작업 전후에 남길 결과 형식
- `QA`: 보안과 정상 작동 점검 항목
- `Failure repair`: 오류가 발생했을 때 원인을 좁히는 방법

이 스킬은 API 연결을 자동으로 대신 승인하는 도구가 아니다. Codex가 할 수 있는 코드 작성·테스트·오류 분석과, 사용자가 직접 해야 하는 로그인·권한 승인·비밀값 입력을 구분하는 작업 안내서다.

### 2. API Guide를 Google Calendar 연결에 적용

첫 실제 적용 대상으로 Google Calendar 일정 읽기를 선택했다.

일정 생성·수정·삭제 권한까지 요청하지 않고, Google Calendar의 비공개 iCal 주소를 Vercel이 읽는 최소 기능부터 구현했다. 이 방식은 OAuth 앱을 새로 만드는 것보다 설정이 단순하고 읽기 전용으로 시작할 수 있다는 장점이 있다.

연결 구조는 다음과 같다.

```text
[Google Calendar 비공개 iCal]
             ↓ 읽기
[Vercel의 Slack 봇]
             ↓ 답장
[휴대폰 또는 PC의 Slack]
```

비공개 iCal 주소는 캘린더 내용을 읽을 수 있는 비밀정보이므로 코드와 GitHub에는 저장하지 않고 Vercel의 `GOOGLE_CALENDAR_ICAL_URL` 환경변수에만 저장했다.

### 3. Slack 일정 조회 기능 추가

기존 학교→집 버스 Slack 봇에 일정 조회 기능을 함께 추가했다. 새로운 봇을 따로 만들지 않고 기존 앱과 대화창을 그대로 사용했다.

현재 확인된 요청은 다음과 같다.

```text
오늘 일정 알려줘
내일 일정 알려줘
이번 주 일정 알려줘
다음 주 일정 알려줘
```

요청 문장에서 기간을 구분한 뒤 해당 날짜 범위의 Google Calendar 일정을 정리해 답하도록 만들었다. 일정이 없는 경우에도 오류가 아니라 일정이 없다는 답장을 보내도록 처리했다.

### 4. Slack DM과 채널 응답 확인

처음에는 기존 봇 DM에서 일정과 버스 답장을 확인했다. 이후 새 Slack 채널에서도 봇을 사용할 수 있도록 다음 설정을 추가했다.

- `app_mentions:read`: 채널에서 봇을 멘션한 메시지를 받는 권한
- `app_mention`: 봇이 멘션됐을 때 Slack이 Vercel로 보내는 이벤트

권한 추가 후 Slack 앱을 워크스페이스에 다시 설치했고, 채널에서 아래와 같이 보냈을 때 답장이 오는 것을 확인했다.

```text
@Bot 오늘 일정 알려줘
```

채널 멘션 기능은 질문에 답하기 위한 기능이다. 밤 11시 자동 알림과는 별개의 설정이다.

### 5. 내일 일정 자동 알림 준비

매일 밤 11시(KST)에 다음 날 일정을 확인하는 Vercel Cron 코드를 준비했다.

현재 설계는 다음과 같다.

- 실행 시각: 매일 밤 11시(KST)
- 확인 대상: 다음 날 Google Calendar 일정
- 전송 위치: `SLACK_DM_CHANNEL_ID`에 지정한 Slack 대화 또는 채널
- 일정이 없는 경우: 메시지를 보내지 않음

Vercel에 다음 환경변수를 추가했다.

- `CRON_SECRET`: 예약 실행 주소를 다른 사람이 임의로 호출하지 못하게 보호하는 전용 무작위 값
- `SLACK_DM_CHANNEL_ID`: 자동 알림을 받을 Slack 위치의 ID

두 값은 `Production`의 Sensitive 환경변수로 저장했고 사용자가 직접 재배포했다. 그러나 실제 밤 11시 실행과 Slack 수신 결과는 아직 확인하지 못했다. 따라서 자동 알림은 완료가 아니라 **설정 완료·실행 미검증 상태**다.

### 6. 코드 검증

일정 기간 계산, iCal 해석, 오류 메시지 보호, 다음 날 알림 생성, 예약 실행 인증을 포함한 테스트를 실행했다.

```text
22개 테스트 실행
22개 통과
```

코드 단위 테스트는 통과했지만 예약 실행은 실제 Vercel Cron 호출과 Slack 수신을 내일 별도로 확인해야 한다.

## 막힌 점과 해결 과정

### 1. 잘못된 Calendar 주소로 인한 `500` 오류

처음에는 Google Calendar의 공개 형식 주소를 Vercel 환경변수에 입력했다. 일정 요청 시 Slack 이벤트 함수에서 `500` 오류가 발생했고, Vercel 로그에서 Calendar 주소 요청이 `404`로 실패한 것을 확인했다.

Google Calendar 설정의 올바른 비공개 iCal 주소로 교체하고 재배포한 뒤, Slack에서 일정이 없다는 정상 답장이 오는 것을 확인했다.

정리하면 공개 주소 문제는 **Slack 일정 조회 오류의 원인**이었다. 아직 검증하지 않은 밤 11시 자동 알림의 성공 여부와는 구분해야 한다.

### 2. Slack 서명값 오류로 인한 `401`

Vercel의 `SLACK_SIGNING_SECRET` 값이 Slack 앱의 실제 Signing Secret과 맞지 않아 Slack 요청이 `401`로 거부됐다. 이때는 일정뿐 아니라 기존 버스 질문에도 답하지 않았다.

같은 Slack 앱의 Signing Secret을 다시 확인해 Vercel 환경변수를 수정하고 재배포했다. 이후 기존 버스 답장이 다시 오는 것으로 Slack 요청 인증이 복구됐음을 확인했다.

봇의 표시 이름을 `Bot`으로 바꾼 것은 오류 원인이 아니었다. 동일한 Slack 앱의 이름만 바꾼 것이므로 토큰과 이벤트 연결은 유지된다.

### 3. 코드 수정 후 재배포 전에는 이전 동작이 유지됨

처음 `내일 일정 알려줘`라고 물었을 때 오늘 일정이 표시됐다. 기간 구분 코드는 수정됐지만 운영 Vercel에 새 버전이 아직 배포되지 않은 상태였다.

재배포 후 오늘, 내일, 이번 주, 다음 주를 구분해 답하도록 반영했다. 이를 통해 로컬 코드 수정과 실제 서비스 반영은 별개의 단계라는 점을 다시 확인했다.

### 4. 새 Slack 채널에서 답장이 오지 않음

새 채널에 봇을 추가했지만 처음에는 멘션에 답하지 않았다. 기존 설정은 DM 이벤트만 받을 수 있었고 채널 멘션 권한과 이벤트가 없었다.

`app_mentions:read` 권한과 `app_mention` 이벤트를 추가하고 Slack 앱을 다시 설치한 뒤 채널 답장을 확인했다.

### 5. 자동 알림 설정과 질문 답변 설정의 혼동

채널에서 질문에 답하는 기능과 매일 밤 11시에 먼저 알려주는 기능을 같은 설정으로 이해해 중간에 작업 목적이 혼동됐다.

- 채널 질문 답변: `@Bot` 멘션, `app_mentions:read`, `app_mention` 필요
- 자동 알림: Vercel Cron, `CRON_SECRET`, 알림 대상 채널 ID 필요

두 기능을 분리해 설명한 뒤 자동 알림에 필요한 환경변수를 추가했다. 자동 알림은 아직 실제 실행 전이므로 검증 결과에는 포함하지 않았다.

## 오늘 배운 것

### API 연결은 코드만 만드는 작업이 아니다

API 연결에는 코드 외에도 권한, 인증값, 실행 위치, 배포, 실제 결과 검증이 필요하다. 한 단계가 성공해도 전체 기능이 성공한 것은 아니다.

### 최소 권한으로 시작할 수 있다

Calendar 일정을 읽는 것이 목표라면 처음부터 일정 생성·수정·삭제 권한을 받을 필요가 없다. 이번에는 비공개 iCal을 읽는 범위로 시작해 필요한 권한과 구현 복잡도를 줄였다.

### 환경변수마다 역할이 다르다

- `GOOGLE_CALENDAR_ICAL_URL`: Calendar 내용을 읽는 주소
- `SLACK_SIGNING_SECRET`: Slack에서 온 요청이 진짜인지 확인
- `SLACK_BOT_TOKEN`: Slack으로 답장을 전송
- `CRON_SECRET`: 예약 실행 요청을 보호
- `SLACK_DM_CHANNEL_ID`: 자동 알림을 보낼 Slack 위치 지정

비밀값은 코드나 보고서에 기록하지 않고 Vercel에만 보관해야 한다.

### 질문 응답과 예약 알림은 다른 기능이다

질문 응답은 사용자의 Slack 메시지가 시작점이고, 예약 알림은 정해진 시간이 시작점이다. 같은 봇이 메시지를 보내더라도 필요한 설정과 검증 방법이 다르다.

### `api-guide`의 역할

`api-guide`는 서비스마다 다른 API를 자동으로 만들어 주는 도구가 아니다. 새로운 서비스를 연결할 때 다음 질문을 빠뜨리지 않도록 돕는 반복 작업 기준이다.

- 정말 API가 필요한가?
- 읽기만 필요한가, 쓰기도 필요한가?
- 최소 권한은 무엇인가?
- 어떤 작업을 Codex가 하고 어떤 승인을 사용자가 해야 하는가?
- 비밀정보는 어디에 저장하는가?
- 무엇을 확인해야 완료라고 말할 수 있는가?
- 실패하면 어떤 순서로 원인을 찾고 되돌리는가?

이 기준은 이후 Google Calendar의 다른 기능이나 주식 정보 API를 연결할 때도 다시 활용할 수 있다.

## 보안과 남아 있는 연결

- Google Calendar 비공개 iCal 주소는 Vercel Sensitive 환경변수에만 저장
- Slack Bot Token과 Signing Secret은 Vercel Sensitive 환경변수에만 저장
- Cron 전용 비밀번호와 Slack 알림 위치 ID도 Production 환경변수로 저장
- Calendar 일정은 읽기 전용이며 생성·수정·삭제 기능은 없음
- Slack 봇에는 DM 읽기, 메시지 전송, 앱 멘션 읽기 권한이 남아 있음
- 비공개 iCal 주소가 노출되면 Google Calendar에서 주소를 재설정해야 함
- Slack 비밀값이 노출되면 Slack에서 재발급한 뒤 Vercel 환경변수도 교체해야 함
